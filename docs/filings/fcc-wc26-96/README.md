## What the comment argues

1. **A price test for competitors.** A provider should count as an "unsubsidized competitor", and so trigger a cut in a carrier's high-cost support, only if its qualifying plan is priced at or below the Commission's reasonable comparability benchmark derived from the Urban Rate Survey ($96.46 a month for 100/20 Mbps in 2026, outside Alaska; DA 25-1088). Map availability alone is not enough, because availability is a quantity signal, not a price signal, and section 254(b)(3) speaks to rates.
2. **Treat mapping data as a versioned register.** Each support decision should name the Broadband Data Collection release it rests on, and that file should be published and archived. The extract should be reconciled against published totals before use. Support should be reduced only after competing service persists across two collections, reductions should be phased, and support should be restored on the same test in reverse.

## Link to this programme

The second point draws on this repository's September 2026 capture of the USDA Local Food Directories, where the state-by-state API sweep returned 30–80% of the listings in the bulk download and reported no error. See standard 9, *completeness outranks automation*, in `CHARTER.md`. The comment offers this as an illustration of how administrative registers fail silently, not as a claim about the Broadband Data Collection itself.
